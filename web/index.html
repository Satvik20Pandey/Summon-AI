Three things no agent memory does today

Each one is a graph query, not a feature flag.

📞

Decisions made by phone become nodes

Answers, instructions, decisions and preferences you say on the call are written to FalkorDB with an edge to that exact call. Nothing is a flat transcript.

🔁

One memory for every agent

Claude Code, Codex and Cursor read the same graph through one MCP server. handoff() tells an agent what the others did since its last session, and records that it read it.

🧭

Every answer has a path back to you

provenance() walks Decision → Call → Developer: who was running, when you said it, what it replaced, and which agents have consumed it since.

The graph decides whether to call

Track 01: acting on connected data. Quiet hours you mentioned on a previous call, calls in the last hour and the task's priority are read from the graph; the decision is written back as a CallDecision node with its reason, so the Lens can show why your phone did or did not ring.

How it is wired

Stop hooks

Claude Code and Codex run summon hook when they finish. It phones you, waits, and returns {"decision":"block","reason":"…your words…"}, which makes the agent continue with your instruction.

MCP tools

summon_recall, summon_remember, summon_done, summon_inbox. Same server for every agent; SUMMON_AGENT says who is asking.

Voice provider

Calls go through the public developer API of Shravan.ai (POST /v1/calls + signed webhooks). SUMMON_VOICE=mock runs the whole loop with no telephony at all.
