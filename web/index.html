Track 01 · agents that act on connected data

The graph decides
when your phone rings.

Quiet hours you mentioned on an earlier call, how many calls you missed this hour, and how urgent the task is are all read from FalkorDB. The decision is written back as a node, so you can always see why your phone did, or did not, ring.

  • "Don't call me before 9" becomes a Preference, learned on a call
  • Two missed calls in an hour back the agent off for 30 minutes
  • A hard cap stops a runaway agent from draining your wallet

// where did this rule come from?
MATCH (n {id: $id})
OPTIONAL MATCH (n)-[:MADE_IN|GIVEN_IN|LEARNED_IN]->(c:Call)
OPTIONAL MATCH (c)-[:ABOUT]->(t:Task)
      -[:IN]->(:Session)-[:RUN_BY]->(a:Agent)
OPTIONAL MATCH (n)-[:SUPERSEDES]->(old)
RETURN n, c.at, t.title, a.name, old

// what did the other agents do while I was away?
MATCH (t:Task)-[:IN]->(s:Session)-[:RUN_BY]->(a:Agent)
WHERE a.name <> $me AND t.done_ts >= $since
RETURN t, a.name

Track 02 · agent memory and coordination

Memory as a graph,
not a pile of transcripts.

Provenance is a path. Handoff is a relationship between sessions. A changed mind is a SUPERSEDES edge. These are one-hop and three-hop questions in Cypher, answered in milliseconds by FalkorDB on every agent turn.

  • One graph per developer, isolated in a single FalkorDB instance
  • Webhook retries can't duplicate a fact: every write is a MERGE
  • Full-text recall across decisions, instructions and tasks
